# 电商故障信息整理

读取用户本次提供的故障文本或指定文件。缺少输入时说明缺口，不沿用历史故障结论。

## 整理规则

- 区分已确认现象、排查假设、已确定行动和未采纳建议；没有证据不确认根因、影响范围或损失金额。
- 行动项列出任务、负责人、完成日期和原文依据。缺少负责人或日期时写“待确认”，提出建议的人不自动成为负责人。
- 分别记录记录日期、计划验证日期和实际恢复时间；未提供的时间不补造。相对日期只有参照明确时才换算。
- 时间或状态有冲突时保留双方说法，列为待确认；只有明确最终决定才能消除冲突。
- 只整理本次输入，不连接生产系统，不重放支付回调、不改订单状态，也不将整理完成写成故障已修复。

## 输出

1. 故障概况：主题、记录日期、已确认现象及已知影响；缺失项写“未提供”。
2. 已确认安排：列出明确的处理范围、计划和不执行的操作。
3. 行动清单：任务、负责人、完成日期、原文依据四列表格。
4. 待确认问题：根因假设、信息缺口及冲突；没有依据时不补造任务。

用户要求保存时，输出到指定位置的 Markdown 或文本文件；否则直接回复。生成 Word 文件需要相应文档工具。

交付前核对姓名、日期、证据与行动项，确保“计划验证”没有写成“已经恢复”。
