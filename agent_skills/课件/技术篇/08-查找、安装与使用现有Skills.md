# 第 8 章：查找、安装与使用现有 Skills

本章按“选择、安装、调用、检查”的顺序使用已有技能。WorkBuddy 案例生成 Word 故障处理单，Codex 案例认识本地技能目录和调用方式。

## 8.1 先有任务，再找技能

### 把需要的能力说具体

“找一个办公技能”范围太大。可以先写清楚：

```text
我要根据本地故障记录生成可编辑的 Word 故障处理单。
需要包含标题、正文和行动清单表格，并检查排版。
不需要发送邮件，也不需要连接外部文档平台。
```

据此寻找支持 `.docx` 生成与编辑的技能。一个只会总结文字的技能，未必能交付真正的 Word 文件；一个主要操作在线文档的技能，也未必适合本地文件任务。

第三章的 Excel 任务可以用同样方式筛选：是否支持 `.xlsx`、公式、图表和结果核验。Codex 的 Python 项目则先考虑是否需要代码检查、测试或交付说明方面的技能，不必为了使用 Skill 给简单程序增加无关工具。

### 从哪些地方找

优先查看客户端已有技能、官方推荐入口和来源明确的仓库。找到候选后，记录名称、来源链接和版本或下载日期，方便以后复现。

WorkBuddy 的技能页面提供技能市场、已安装列表，以及查找和本地包导入入口。[WorkBuddy 官方技能说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)

不同入口的技能名称可能不同。本章中的“文档类技能”是能力分类，选择时以实际技能名称和说明为准。

## 8.2 安装前，读懂技能说明

打开技能详情和可查看的 `SKILL.md`，先看下面五项：

| 要看什么 | 本次 Word 案例关注什么 |
| --- | --- |
| 用途和触发条件 | 是否明确支持创建或编辑 Word 文档 |
| 输入和输出 | 输入可以是本地文字，输出为真正的 .docx |
| 工作步骤 | 是否包含读取资料、生成文件、检查结果 |
| 依赖与工具 | 是否需要 Python、办公软件或额外程序 |
| 范围和限制 | 是否需要外部账号、联网或发送资料 |

技能安装成功，与依赖准备完成，是两件事。例如，技能带有生成脚本，但环境没有对应解释器，执行仍然会失败。

优先选择步骤少、依赖明确、能处理本地资料的技能。查看附带脚本和资源，确认与任务相关；不要只根据介绍中的“全能”或“自动完成”判断适用性。

## 8.3 WorkBuddy：安装并使用文档技能

### 第一步：查找并安装

打开技能页面，用“Word”“docx”或“文档”查找候选。进入详情，确认用途和依赖后安装，再到已安装列表确认状态。

如果采用本地技能包，则从“添加技能”进入上传入口，选择来源明确、符合当前客户端要求的包。不要把任意一个 Markdown 文件改成压缩包就当作技能包。

官方页面也提供查找技能和创建技能入口。本章使用已有技能；创建方式留到后续章节。已安装技能支持启用和关闭，关闭不等于卸载。[安装与启用说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)

### 第二步：指定技能与本次输入

把第十章的独立[故障记录B.txt](资料/第10章/故障记录B.txt)复制到独立演示文件夹，选择该工作空间。在客户端中明确选择或提及刚安装的技能，再输入：

```text
请使用刚才选择的文档技能，读取故障记录B.txt，
生成当前工作空间中的“订单故障处理单.docx”。

内容包括已确定事项、行动清单、待确认问题。
行动清单使用可编辑表格，列为任务、负责人、完成日期。
原文没有确定的内容写“待确认”，不要补造损失金额或根因。
完成后检查文档内容与排版，并告诉我文件位置和实际完成的检查。
```

文档技能负责通用的文件制作方法，本次提示词仍要说明故障处理单的业务要求。除非技能本身包含故障整理规则，否则不要假设它已经知道我们的固定结构。

### 第三步：观察调用，打开文件

先查看执行过程是否显示读取了所选技能或调用了对应能力，再检查实际文件。界面没有明确显示时，可要求说明本次读取的技能路径和使用的资源，并结合可见记录核对，不能仅凭一句“已使用”下结论。

用 Word 或 WPS 打开文档，核对：

- 小陈负责整理两份JSON样例，2026-10-16前完成。
- 排查说明日期存在2026-10-17与2026-10-18两种说法，尚未确定。
- 中文CSV导出检查的负责人和日期待确认；自动重发支付回调本次不做。
- 行动清单可以编辑，表格没有超出页面，正文没有被裁切。

日期和负责人来自输入，不能因为模板中有示例内容就照搬进成果。

### 第四步：在原任务中继续修改

```text
请在原 Word 文档开头补充故障主题和记录日期。
记录日期以原文为准，不要误用计划修复日期。
保留已经核对的行动清单，保存后再次检查文档。
```

本次记录日期为2026-10-15，生产修复日期尚未确定。这是一个容易核验的小修改，足以展示技能参与文件的持续编辑。

## 8.4 Codex：认识安装范围与调用入口

### 项目级与用户级

项目级技能主要服务当前项目；用户级技能方便在多个项目中使用。当前官方文档列出的本地发现位置包括项目中的 `.agents/skills` 和用户主目录下的 `.agents/skills`，具体范围应结合客户端版本确认。[Codex 技能目录说明](https://learn.chatgpt.com/docs/build-skills)

例如，一个项目级技能的结构可以是：

```text
订单统计项目/
├── main.py
├── 订单数据.json
└── .agents/
    └── skills/
        └── 某个技能目录/
            ├── SKILL.md
            └── 技能所需的其他资源
```

这是路径示意，不是本章新制作的技能。手工安装时保留完整资源，避免把 `SKILL.md` 与它引用的脚本、模板拆开。技能目录与第四章的模型配置目录是不同概念，不要把技能内容粘贴到 `config.toml`。

### 用配套技能确认目录是否正确

可以用第十章提供的 [incident-action-items](资料/第10章/incident-action-items/SKILL.md) 作为来源明确的本地技能：复制完整的 `incident-action-items` 文件夹到项目的 `.agents/skills/` 中，然后在该项目的 Codex 会话里确认它可见。

此技能只提取故障信息，不生成 Word 文件。这样可以单独检查“技能能否被发现与读取”，避免把办公软件依赖和安装位置问题混在一起。技能正文的制作方法在第十章介绍。

### 使用安装器

Codex 官方文档介绍了 `$skill-installer`，可用于安装推荐技能或指定仓库中的技能。[官方安装方式](https://learn.chatgpt.com/docs/build-skills)

在支持该技能的 Codex 对话中输入：

```text
$skill-installer
请列出当前可安装的技能，先不要安装。
我想为一个只使用 Python 标准库的命令行项目寻找代码检查或测试辅助技能。
请说明匹配项的用途、来源和依赖；没有合适项就明确说明。
```

这是在 Codex 对话中发出的请求，不是在 PowerShell 中执行的命令。选定实际候选后，再明确给出准确名称，或仓库地址与仓库内技能路径，要求安装。

不要把仓库名称当成技能名称，也不要假设存在名为“python”的通用技能。没有合适候选时，仍可使用第五章的普通提示词完成检查，后面再制作适合本项目的技能。

### 确认发现并显式调用

Codex CLI 和 IDE 扩展可通过 `/skills` 或输入 `$` 选择技能；桌面端按实际技能入口选择。技能未出现时先核对安装位置和资源结构，再尝试重新启动客户端。[官方调用说明](https://learn.chatgpt.com/docs/build-skills)

选择已经确认适合本项目的检查技能后，可以提出：

```text
请使用刚才选中的技能检查当前 Python 订单统计项目。
重点核对已支付订单口径、组合筛选和 CSV 导出。
先阅读需求与代码，按技能适用范围检查，不安装无关依赖。
不要修改源数据或重写项目。
说明发现的问题、依据和实际运行过的检查。
```

不能把通用代码检查回复包装成技能执行证据。

## 8.5 显式调用与自动匹配怎么比较

首次使用时优先显式选择，确认使用的是哪个技能。确认能运行后，可以在新会话中提出相同类型的任务，但不点名技能，观察客户端是否自动匹配。

例如，在 WorkBuddy 新任务中要求“根据故障记录生成带行动清单表格的 Word 纪要”，然后查看执行记录。没有自动匹配时，检查技能是否启用、描述是否匹配、该客户端是否允许自动调用。

比较时保持输入和输出要求一致，并使用不同的输出文件名。不要断言使用技能一定更快，也不要把一次成功当成稳定性证明。

Codex 选择 OpenAI 或 DeepSeek 路线时，都可以按“发现、读取、执行、结果”四步检查。切换提供方并新建会话后重新确认技能状态。

## 8.6 常见问题，按发生的位置排查

| 现象 | 优先检查 | 下一步 |
| --- | --- | --- |
| 技能列表找不到 | 安装范围、目录结构、当前客户端 | 核对实际路径，必要时重启 |
| 能看到但未使用 | 是否启用、描述是否匹配、调用设置 | 先显式选择，再观察记录 |
| 读取后报缺少程序 | 解释器、工具或依赖是否具备 | 按技能说明准备环境 |
| 找不到模板或脚本 | 是否只复制了 SKILL.md | 补齐原包中的相对路径资源 |
| 文件生成但内容错误 | 原文、业务规则和任务要求 | 指出具体错误，重新核验 |
| 换模型后执行失败 | 技能加载、模型工具调用和本地环境 | 分步骤定位，不直接重装所有技能 |

遇到失败时，可以让 Agent 先回答：使用的是哪个技能、执行到哪一步、缺少什么、哪些文件已经生成。这样更容易决定下一步，而不是重复点击安装。
