# 第 2 章：WorkBuddy 上手与任务管理

本章以电商 IT 值班交接为例，处理3,260行随机生成的工单导出。通过资料盘点、清洗、超时筛选、Word交接报告和结果修订，认识 WorkBuddy 如何管理一项需要多个步骤完成的任务。

## 2.1 安装、登录与初始设置

### 下载和安装

访问 [WorkBuddy 官网](https://www.workbuddy.cn/)，选择 Windows 安装包。注意选择 WorkBuddy 产品，避免将其他产品的安装包或操作界面混用。

下载完成后，双击安装包，按照向导选择安装位置并完成安装。如果没有特殊需要，可以使用向导提供的默认选项。

当前官方安装说明要求 Windows 10 及以上的 x64 系统；ARM64 设备应另行查看当前版本的支持说明。[Windows 安装指南](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Installation-Win-Guide)

### 登录并返回客户端

打开 WorkBuddy，点击登录，按提示在浏览器完成身份验证。个人用户可以使用页面提供的微信扫码等登录方式。浏览器提示成功后，返回客户端，确认已经进入任务界面。

安装和登录是两个步骤：安装成功说明软件已在电脑上，登录成功后才能使用相应账号的服务。在浏览器完成登录后，返回客户端继续创建任务。[开启第一个任务](https://www.workbuddy.cn/docs/workbuddy/FirstTask)

### 认识模型和用量

模型选择入口用于决定这次任务使用的模型或处理模式。当前官方文档介绍了模型模式选择及自定义模型配置；实际可选内容应以账号界面为准。本章先选择账号中可用的默认选项，开始本章的分阶段任务。[模型配置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)

还应认识账号中的用量、积分或套餐相关入口，知道在哪里查看可用额度。具体模型名称、赠送额度和价格容易变化，不需要在这一章记住固定数字。如果界面提示额度不足，先查看提示对应的账号用量，再决定下一步操作。

演示前确认三件事：软件已登录、当前模型可用、网络连接正常。需要核对版本时，可在头像菜单中的“检查更新”等入口查看。

## 2.2 看懂任务界面

### 先认识三个区域

进入一个任务后，可以先按下面的方式理解界面：

| 区域 | 主要用途 | 本章中怎样使用 |
| --- | --- | --- |
| 左侧任务列表 | 找到、切换和继续已有任务 | 回到工单清洗或交接报告任务 |
| 中间对话区 | 输入要求，查看执行进展，补充说明 | 提出整理要求，再追加修改 |
| 右侧结果区 | 查看生成的文件及相关内容 | 打开工单清单与交接报告 |

右侧区域可能处于收起状态，可以通过对话顶部的详情面板入口打开。这里的重点是找到“提要求的地方”和“看成果的地方”。[任务对话](https://www.workbuddy.cn/docs/workbuddy/Conversation)、[结果查看](https://www.workbuddy.cn/docs/workbuddy/Results)

### 新建任务与选择工作空间

点击“新建任务”，开始一次新的工作。创建时可以选择工作空间，也就是这次处理文件所使用的目录；不同版本可能将入口显示为文件夹选择按钮。

例如，在电脑上准备一个“WorkBuddy演示”文件夹，将本章的“输入资料”目录放进去，再选择该文件夹作为工作空间。这样输入与生成文件都容易找到。[创建任务](https://www.workbuddy.ai/docs/workbuddy/Create-Task)

工作空间与任务可以这样区分：**工作空间对应这项工作使用的资料位置，任务对应一次具体的处理过程。** 同一个工作空间可以继续开展其他相关任务。

### 提供资料与处理授权

除了输入文字，还可以将文件拖入输入框，通过上传入口添加，或使用界面支持的文件引用方式。文件名出现在输入区域后，再发送要求。[文件与图片输入](https://www.workbuddy.cn/docs/workbuddy/Conversation)

选择工作空间后，如果软件提示文件访问授权，先看清授权的目录与操作。本章只处理演示文件夹。写明输入文件和输出位置，也能减少任务范围不清造成的问题。

需要区分两件事：把资料提供给 Agent，是让它知道依据什么工作；授权，是让运行环境允许相应操作。只有在资料可访问时，它才能真正读取内容。

### 输入文件、对话和结果文件

| 内容 | 作用 | 本例 |
| --- | --- | --- |
| 输入文件 | 提供本次任务的事实 | 运维工单.csv、案例说明与口径.md |
| 对话 | 表达目标、补充要求、查看进度 | 要求整理行动项 |
| 结果文件 | 保存可继续使用的成果 | 值班交接报告-v1.docx |

对话中出现了表格，不等于已经生成 Word 文件。文件保存后，还要按返回路径打开，确认内容可编辑、事实正确。原始记录作为核对依据保留。


## 2.3 案例背景：从数千条工单整理值班交接

值班工程师接手三个门店的运维事务，需要回答：当前有多少未结工单，哪些已超时，哪些高优先级事项应先处理，哪些事项无人负责。交接文档必须能追溯到具体工单，而不是只给一段笼统总结。

配套[输入资料](资料/第02章/输入资料)包含工单CSV、[处理口径](资料/第02章/输入资料/案例说明与口径.md)和[交接背景](资料/第02章/输入资料/交接背景.md)。原始数据有3,260行，涵盖3,200个工单编号、3家门店、5个业务系统和4级优先级。

资料采用固定随机种子生成，并刻意保留完全重复行、同编号冲突和负责人缺失。人员、事件与订单关联均为虚构。基准时间固定为2026-10-12 12:00（北京时间），重新打开任务时不改成当天时间。

准备工作空间：

~~~text
电商IT值班交接/
├── 输入资料/
│   ├── 运维工单.csv
│   ├── 案例说明与口径.md
│   └── 交接背景.md
└── outputs/
~~~

只把输入资料交给WorkBuddy。[结果核对目录](资料/第02章/结果核对)留作输出检查，不让Agent直接读取其中的预期答案。

本章交付不只是一个Word：还要有完整有效工单、冲突版本、完整超时清单与处理记录。这些文件可以支持查错和继续处理，Word只呈现重点。

## 2.4 第一个阶段：先盘点，再规划

新建任务，命名为“门店运维工单核查-20261012”，选择工作空间。发送：

~~~text
请读取输入资料目录中的文件，先完成资料盘点与处理计划，不要直接生成Word。

列出实际文件名、CSV字段、全量数据行数、工单编号数量、时间范围。
只预览少量记录说明结构，但总数必须通过实际读取全文件取得，不能从前20行推断。
先读“案例说明与口径.md”，指出完全重复、编号冲突、负责人缺失分别如何处理。
把任务拆成：盘点、清洗、超时筛选、交接报告、检查与修订。
每个阶段说明输入、输出与完成标准。

将计划保存为outputs/任务计划.md，不修改输入资料。
后续需要程序处理时可以使用当前环境支持的文件或代码工具；
若不能实际读取全量文件，请明确说明，不估算。
~~~

这一步观察三个方面：是否找到真实文件，是否读全量记录，是否区分重复和冲突。聊天中的“已读取”不够，应该有可核对的文件名、字段、行数和处理计划。

几千条记录不需要逐行贴入对话。让文件留在工作空间，由工具读取、统计和筛选，再把摘要交给模型解释，更容易保持记录完整。

## 2.5 第二个阶段：清洗并保留审计记录

在同一任务中继续：

~~~text
按已经读取的口径执行工单清洗，结果写入outputs。

1. 先去除所有字段完全一致的重复行，记录删去的行数。
2. 同一ticket_id内容不同的，隔离该编号全部版本。
   不按第一条、最后一条或更新时间擅自选一个版本。
3. 负责人为空的记录保留，展示时写“待指派”，不要编造负责人。
4. 输出有效工单.csv、冲突工单.csv、数据质量摘要.json。
5. 摘要分别记录原始行数、完全重复行数、冲突编号数、冲突版本行数、有效工单数。
6. 在任务计划.md更新本阶段状态，写明已生成文件。
完成后先报告清洗结果，暂不编写Word。
~~~

固定样本应满足：

| 指标 | 预期 |
| --- | ---: |
| 原始数据行数 | 3,260 |
| 完全重复、需删除的多余行数 | 40 |
| 不同工单编号 | 3,200 |
| 有内容冲突的工单编号 | 20 |
| 隔离的冲突版本行数 | 40 |
| 进入后续分析的有效工单 | 3,180 |
| 有效工单中负责人缺失 | 80 |

行数关系为：3,260 − 40 − 40 = 3,180。不是3,260 − 40 − 20，因为每个冲突编号包含两个需要隔离的版本。

打开冲突文件，可见同一工单编号存在不同负责人。这个场景没有权威版本依据，不能让Agent自行决定谁负责。

## 2.6 第三个阶段：形成真正可用的交接清单

本例未结状态为“待处理”和“处理中”。P1、P2、P3、P4从创建到基准时间的等待阈值分别为4、12、24、48小时，严格超过才计超时。已解决和已关闭不纳入未结超时指标。

继续发送：

~~~text
读取outputs/有效工单.csv，按口径计算未结、超时、P1/P2超时和未指派情况。
基准固定2026-10-12T12:00:00+08:00；不要用电脑当前时间。
计算等待时长使用完整时间，展示时可以四舍五入，判断超时不能先四舍五入。

输出全部超时工单.csv、高优先级超时工单.csv，以及交接Top20.csv。
Top20按优先级P1在前、创建时间更早在前、ticket_id升序排序。
列出工单编号、门店、系统、优先级、状态、等待小时、阈值、负责人和现象。
同时输出按门店、系统和优先级的汇总，保留完整清单。
负责人缺失与超时可能重叠，不把标签数量相加当成独立工单数。
更新任务计划.md，保存关键指标到交接指标.json。
~~~

核对结果：

| 指标 | 预期 |
| --- | ---: |
| 未结工单 | 1,325 |
| 未结且超时 | 1,108 |
| P1/P2且超时 | 383 |
| 未指派且超时 | 63 |

Top20的前三个工单应为INC00668、INC02044、INC02841。Top20只是一份展示清单，不代表系统只有20个需要处理的事项。完整高优先级超时清单仍有383条。

## 2.7 第四个阶段：编写 Word 值班交接报告

在完成统计后继续：

~~~text
根据已保存的清洗摘要、交接指标、交接Top20和输入资料/交接背景.md，
生成真正可编辑的Word文件outputs/值班交接报告-v1.docx。

报告包含：
一、交接摘要：当前范围、基准时间、未结与超时概况；
二、数据质量：重复、冲突、缺失，以及排除规则；
三、重点交接：Top20可编辑表格，包含工单编号和负责人；
四、分系统处理建议：建议与事实分开，没有承诺的日期写待确认；
五、附件索引：完整清单文件名及用途。

不要将全部3,180条有效工单塞入正文。
不要把客服现象改写成已证实根因，不推断损失金额或影响用户数。
使用A4页面、清晰标题、重复表头和合适的列宽。
表格不能变成图片；正文与CSV、JSON的数字必须一致。
告诉我实际保存路径。
~~~

用Word或WPS打开结果，检查标题、分页、表格可编辑性与数字。报告应能让接班人迅速定位工单；不能只写“应加强监控、及时处理”而不给编号和依据。

参考摘要可以写为：

> 本次核查3,260行工单导出。去除40行完全重复记录，隔离20个冲突编号对应的40行版本后，取得3,180条有效工单。其中未结1,325条，超时1,108条，P1/P2超时383条。完整清单另附，正文列出优先处理的20条。负责人缺失80条，其中63条已超时，仍需指派。

这段摘要只陈述指定快照的事实，不代表全部真实业务，也不证明系统已恢复。

## 2.8 任务管理：暂停、继续、拆分与交接

多阶段任务的管理，重点是知道“已经完成什么、成果在哪里、下一步依赖什么”。

| 场景 | 处理方式 |
| --- | --- |
| 同一份报告改版式或补说明 | 在原任务继续，指定版本和修改范围 |
| 需要暂停 | 查看已落盘文件，把已完成/未完成内容保存到任务计划 |
| 原任务失败 | 先检查最后成功的阶段与文件，避免重复清洗或重复覆盖 |
| 第三章开始订单核对 | 新建任务，使用独立工作空间 |
| 新任务接手已有工作 | 显式提供任务计划和成果文件，不假设能看到旧任务全部上下文 |

停止执行后，已生成文件不会自动撤销。恢复时可以发送：

~~~text
先读取outputs/任务计划.md与现有成果，列出已完成和未完成阶段。
检查有效工单.csv与交接指标.json是否存在且范围一致。
只继续未完成的报告阶段，不重复修改原始文件，不覆盖v1。
如果缺少必要中间结果，指出缺失文件后再处理。
~~~

任务列表支持查找并继续已有任务，也可通过任务菜单打开所在文件夹。相关入口可参阅[WorkBuddy任务管理](https://www.workbuddy.cn/docs/workbuddy/Task-Management)。将任务改成有日期与业务含义的名称，比保留“新任务”更容易找回。

## 2.9 演示两种修改：内容修正与版式修改

假设报告把20个冲突编号误写成“仅删除20行”，应从上游修正：

~~~text
请核对冲突清单：应区分冲突编号数与冲突版本行数。
根据实际CSV重新验证行数守恒，同时检查JSON、Top20与Word是否受影响。
保留v1，修正后生成值班交接报告-v2.docx，并记录修订原因。
不要只改Word里的一个数字。
~~~

如果内容已正确，只想让负责人更快阅读，则限定在版式层：

~~~text
以值班交接报告-v1.docx为基础，另存管理摘要版.docx。
首页给出关键指标与三项待决策事项，Top20保留在后文。
保持全部统计和工单编号不变，不重新分配负责人，不增加恢复承诺。
~~~

打开两个版本比较：修改应该落在要求的范围内。CSV是否一致、Word是否可编辑、文件是否真实保存，都要分别检查。[结果查看说明](https://www.workbuddy.cn/docs/workbuddy/Results)

## 2.10 从一次交接到可复用的工作方法

这次任务已经形成输入口径、分步计划、清洗审计、关键清单、Word成果和修订记录。它们共同构成可复用的工作方法。

以后将同一类文件放入工作空间，可以沿用任务步骤；如果进一步制作Skill，就把稳定的清洗规则、SLA、排序规则和报告结构保存起来。Skills的详细制作放在后续章节。

本章的3,260行数据已经配齐，可直接用于演示。生成与独立校验脚本见[业务数据工具](资料/WorkBuddy业务数据工具/README.md)，不要求先学习Python。第三章继续使用更大规模的订单、支付和发货资料，制作多表Excel与Word核对报告。
